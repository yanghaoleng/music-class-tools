# 手机性能优化 · 2026-10-22

问题来自实时绘制和重复计算的叠加，音频侧也有不必要的节点创建。特别是 Safari/WebKit：音频尚被自动播放策略挂起时，旧版扫描画面本身就出现了明显掉帧。

基线版本 `7e0b157`；对照均使用隔离浏览器数据，不接触用户作品。

## 量测

### WebKit：390 × 844、DPR 3，30 条线 / 12,000 个点

旧版和新版均使用开发构建、本机 Playwright WebKit。观察 4 秒的 requestAnimationFrame 回调间隔；两边 AudioContext 均为 `suspended`，测试的是进入页面后未触摸时的扫描画面。

| 指标 | 旧版 | 优化后 |
| --- | ---: | ---: |
| 回调帧率 | 约 8 fps | 约 60 fps |
| P95 帧间隔 | 195 ms | 18 ms |
| 超过 50 ms 的帧间隔 | 22 | 0 |

原始数据：[webkit-comparison.json](performance/webkit-comparison.json)。此前一轮独立运行也得到约 8 → 60 fps 的相同趋势。

### Chrome：生产构建，390 × 844、DPR 3、CPU 四倍降速

30 条线，每条 400 个点；两声部（电钢、空气合成器），120 BPM、四分之一拍，4 秒观察窗口。使用无手势音频播放策略，区分完整播放、停用视觉特效、音频单独运行、视觉单独运行、暂停五种模式。

| 指标 | 旧版 | 优化后 |
| --- | ---: | ---: |
| 完整播放的主线程 TaskDuration | 1,692 ms | 129 ms |
| 完整播放的 ScriptDuration | 965 ms | 43 ms |
| 完整播放 P95 帧间隔 | 33.3 ms | 16.7 ms |
| 完整播放 >50 ms 帧间隔 | 7 | 0 |
| 音频单独运行的主线程时间 | 155 ms | 40 ms |
| 暂停时的主线程时间 | 280 ms | 18 ms |
| 完整播放 JS 堆 | 约 15 MB | 约 11 MB |

完整播放主线程耗时在本轮对照中降低约 92%。原始数据：[之前](performance/chromium-before.json)、[之后](performance/chromium-after.json)。关闭滤镜一项并不能解决旧版重复采样、React 更新和路径生成的开销。

这些是本机的单次匹配负载测试，包含运行时波动，不是 iPhone 实机成绩。requestAnimationFrame 间隔不等于硬件屏幕实际呈现帧率；Chrome TaskDuration 不包含原生音频 DSP 线程，也不能完整计入 GPU 成本。WebKit 测试另外验证触摸后 AudioContext 实际运行和非零音频输出。

## 改动

- 实时画布改用分层 Canvas 2D；已完成笔触和可发声笔触分别缓存。播放只复制 24 CSS px 的窄条，扫描线独立变换，不再触发整幅 React 重绘、全屏 SVG 噪声/位移滤镜和路径字符串生成。高亮仍只加深线条，没有节点或圆环。
- 颗粒笔触改为一次生成、按颜色缓存的纹理。绘画原地追加采样点，每帧只绘制新线段；每次手势读取一次画布几何尺寸。完成一条线时只向静态层追加该线。撤销、擦除、声部静音和尺寸变化才重建必要缓存。
- DPR 上限为 2，每层不超过 250 万像素；卸载时释放画布存储。iPhone 的 3 倍屏不会再令每个绘制层都扩大为九倍 CSS 像素面积。
- 播放时使用按音符时间槽编好的索引，复用未修改线条的采样；已编译文档只保留最近四份。活跃绘画单独采样，不把可变输入放入不可变缓存。测试逐步比对原始算法，覆盖反向路径、竖线、交叉、点、32 音上限、静音、独奏与移调。
- 合并整数正弦/三角谐波为缓存的 PeriodicWave。例如电钢每音由三个振荡器变为一个；保留失谐、非整数泛音、滤波、颤音和滑音。八种涉及合并的音色，44.1 kHz 下 C4 对照波形误差均低于 0.1% RMS。
- 连音画笔的试听复用振荡器；延续音高而不反复创建整套长尾音。停止播放会断开旧输出和压缩器，避免长会话残留输出节点。调度跳过已经错过的时间槽，不补播积压；仍按音频时钟提前调度。
- 暂停、阻断式浮层打开时停止不必要的画面循环。手机使用纸面与透明度层次，移除实时 backdrop blur；浮层过渡只动画透明度、位移和缩放。桌面分栏保持可边画边播放。
- 作品缩略图进入附近可视区域才生成矢量内容，取消缩略图的颗粒滤镜。自动保存等待落笔和空闲时段；pagehide 保留同步补存。长 WAV 的 PCM 编码分块让出主线程。

没有改变作品格式、音阶、时间映射、复音上限、音色选择或现有作品数据。

## 验证

- `npm test`：12 项模型与索引对照测试。
- `npm run test:browser`：真实音频解锁、未抬笔发声、绘画、擦除、撤销、保存刷新、搜索分类、导入导出、WAV、快捷键、图标、浮层焦点和响应式。
- `npm run test:electronic`：12 种音色实际渲染，8 种连音相位复用、无断音、尾音释放，分栏与移动浮层。
- `npm run test:audio`：合并前后波形与响度的量化对照。
- `npm run test:mobile`：Chrome / WebKit，DPR 3 手机尺寸；实际像素、静态层在播放时不重绘、输入新增线段量、暂停、触摸、保存恢复及非零音频输出。60 次输入移动只需要 121 次路径线段操作、1 次几何读取，已完成画布只追加绘制一次。
- `npm run profile:mobile`：生产预览上的 Chrome CPU4x 分组量测。
- `npm run profile:webkit`：WebKit 帧间隔量测；`XIANJI_BEFORE_URL` 可指定基线预览，与 `XIANJI_URL` 指向的新版顺序对照。

源码导入型测试（音色与波形）使用开发服务器。其他测试也可用 `XIANJI_URL` 指向生产预览或线上版本。所有写入只发生在测试浏览器的隔离存储中。
