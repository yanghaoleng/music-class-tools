# 刷新后首次出声与 iPhone 媒体会话

## 原因与处理

音色全部在浏览器合成，没有大型音源文件需要下载。刷新时音频上下文可能等待浏览器认可的手势；原实现又从当前扫描位置加入播放，遇到前部空白就必须等待。对照作品为 8 小节、96 BPM、唯一音符在 x=0.9，原调度首音位于 17.96875 秒，探针在上下文已运行时仍检测不到声音。

现在进入页面一次性预热可复用的波形和打击乐缓存，不启动额外音符；首次音频连接直接定位第一个有音符的节拍。暂停后继续保留位置，作品与导出中的休止不改变。页面级捕获 pointerdown、pointerup、touchend、click、keydown，每次从可信手势同步重试解锁，不被加载时悬而未决的 resume Promise 阻塞；暂停按钮和空格不触发额外解锁。提示区按真实状态显示准备中或轻触启用。

Safari 支持时，创建上下文前设置 navigator.audioSession.type = playback。旧版 iOS 才加载本地 4044 字节、0.25 秒的 PCM WAV，通过未静音的循环媒体元素保持媒体播放通道，合成声音仍直出 Web Audio。暂停时停止该兼容元素；无麦克风权限和外部音源。

## 验证

运行 npm run test:startup，使用隔离的 Chrome 与 WebKit 手机尺寸上下文，真实采集合成输出波形，首音触发不依赖绘画试听。覆盖原生模式、模拟仅 touchend 解锁且首次 resume 永久等待、模拟旧版 iOS 无 audioSession API 三种路径。模拟只能验证兼容代码和媒体文件解码，不能代表实体 iPhone 硬件静音键验收。

本地测得触摸至首音：Chrome 60/61/60 ms，WebKit 32/47/100 ms（原生 / touchend / 旧版兼容），均低于 1 秒阈值。原生 WebKit 确认 playback 类型；兼容模式确认媒体加载、未静音循环和暂停停止。保存笔触坐标保持不变。

另有现有端到端测试覆盖首次画线解锁、实时试听、WAV 导出、手机画布性能、暂停及刷新保存。实体 iPhone Safari 静音键与蓝牙设备仍需实机确认。浏览器首次手势限制无法由预加载绕过，刷新后若自动播放被拦截，轻触画布或控件即可启动。

依据：[WebKit 237322](https://bugs.webkit.org/show_bug.cgi?id=237322)（Web Audio 的 ambient 会话受静音开关影响，支持 playback 会话时可按媒体播放）。
